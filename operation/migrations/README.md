Per-tenant D1 schema migrations, applied by `../migrate-tenant-dbs.ts` (one `TenantMigration` per file, see `types.ts`; the runner records the applied names in each tenant DB's `_tenant_migrations` table).

Numbering starts at 0006: migrations 0001–0005 (content list-id, flow counts, content has-face, content trigger dedup, user post-count) were folded into `admin/src/services/tenant-init-sql.ts`'s `TENANT_DB_INIT_SQL` when user/content moved back to per-tenant D1 (2026-07-26 restore), so they only reach FRESH databases. `0006-user-verified-type` exists precisely because that fold does nothing for an EXISTING tenant DB: one provisioned before `verified_type` was a column still needs the `ALTER TABLE`. Future per-tenant schema changes go here as new `TenantMigration` files.
